SysChecks 1.3.0 is the release where the command line stops second-guessing you. Everything now reads as `syschecks <thing> <verb>` — `updates check`, `updates apply`, `kernel status`, `users list`, `schedule enable updates --scope security` — and jobs are turned on and off with real `enable`/`disable` verbs instead of a `--disable` flag bolted onto the command that created them. A single `-o/--output text|json|json-pretty` replaces the assortment of per-command JSON flags, and it tab-completes, as do job names and `--scope` values. Every command you already type keeps working, so nothing on your fleet breaks the moment you upgrade; `syschecks migrate --apply` quietly rewrites the cron and Zabbix files that still reference the old spellings, and the installers now run it for you.

The other half of this release is about things going wrong quietly. If a repository loses its GPG key or vanishes from the internet, neither `apt` nor DNF5 will tell you — both happily exit 0 while your update counts silently go stale. SysChecks now reads what those tools actually print and reports broken repositories right on the banner, so a repo that disappeared shows up at login instead of six weeks later. Along the way we fixed three real bugs on Fedora and DNF5: the banner was reporting 10 security updates on a host that had 59, and 1 system update on a host that had 174. Unattended update runs also pick a random start delay now, so a rack of guests no longer hammers the same hypervisor at 04:15 sharp.

One change needs your attention before you upgrade: `syschecks kernel cleanup` now **removes** old kernels by default rather than previewing them. Use `--dry-run` for the old behaviour. Run it by hand and it will list the packages and ask before doing anything; `--execute` still works and existing cron jobs are unaffected.
