SysChecks 1.3.1 brings Alpine guests into the normal update workflow with a native `apk` backend. The same static Linux binaries already run on musl, so there is no separate Alpine download: system update checks, cache refreshes, full-system apply, banners, and migration all use the regular release assets.

This patch also closes two quiet but dangerous visibility gaps. An unsupported system can no longer return a fully-patched-looking report with zero updates and exit 0, and restrictive root umasks can no longer make cron jobs or the update cache visible to root while a regular user’s login banner claims they are missing. Existing `0600` files are repaired by `syschecks migrate --apply`.

Alpine’s boundaries stay explicit instead of being papered over: apk has no security-only advisory channel, so those JSON values are `null` with an `unsupported` status; kernel cleanup is a no-op because apk replaces kernels in place; and scheduled jobs require `cronie`, since BusyBox `crond` ignores `/etc/cron.d`.
