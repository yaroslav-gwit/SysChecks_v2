SysChecks 1.3.3 fixes misleading status output on hardened systems. When `/etc/cron.d` was intentionally root-only, a regular-user banner interpreted the permission error as disabled schedules; a missing update cache also produced a made-up timestamp and healthy zero-update checks.

Schedule state now falls back to a trusted root-owned cache when the live cron directory cannot be read. Missing or untrusted update data stays explicitly unknown and unhealthy, without weakening the host's directory permissions.
