SysChecks 1.2.0 makes the login banner a focused exception dashboard: healthy checks stay quiet so operators see only conditions that need attention. Low disk space appears once a writable filesystem crosses 90% used, multiple logged-in users are called out, kernel reboot or buildup warnings appear only when actionable, and pending updates appear only above zero. The installed version plus self-update state live in the top-right border, while disabled or conflicting OS-update policies are highlighted in red; `banner --all` restores every healthy and suppressed detail for debugging.

The user-login table has also been tightened for normal SSH terminal widths and now parses real `who` and `last` output consistently, including the last remote host in JSON. For ongoing maintenance, `syschecks cron` now provides a live schedule dashboard, every cron type has a matching disable path, conflicting security/full-update schedules replace each other with a clear warning, and `cron kernels` can schedule weekly cleanup through the guarded `kernel cleanup --execute` path; the running kernel and a recent fallback are always retained.
